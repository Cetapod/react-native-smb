Release notes

Changes in each 1.1 release, newest first. For earlier releases, see the v1.0 release notes.

1.1.0

November 3, 2026

Streaming directory listings, one listing engine for every directory walk, server-side file copy, and pipelined delete and copy.

Breaking changes

listDirectory takes an options object. recursive is gone; maxDepth alone decides the depth.

migrate-list.ts
// before
smb.listDirectory(path, false, -1);
smb.listDirectory(path, true, -1);
smb.listDirectory(path, true, 2, true);

// after
smb.listDirectory(path);
smb.listDirectory(path, { maxDepth: -1 });
smb.listDirectory(path, { maxDepth: 2, includeSecurityDescriptor: true });

The old positional signature is not supported; extra arguments are ignored, which usually gives a single-level list.

OptionDefaultMeaning
maxDepth00: this folder only. > 0: nested children up to that depth. -1: unlimited.
includeSecurityDescriptorfalseFetch the SD of every entry (one request per entry; costly on large folders).
batchSize10Ready top-level entries per streamed batch (batches also flush every 100 ms).

getPathInfo no longer returns children. Folders expose childCount only; list their contents with listDirectory.

migrate-info.ts
const info = await smb.getPathInfo('/Media').result();

info.childCount;                                           // was info.children.length
const items = await smb.listDirectory('/Media').result();  // was info.children

New

  • Streaming listings. listDirectory returns an SmbListTask. subscribeEntries(batch => …) delivers top-level entries while the listing runs and replays earlier batches to late subscribers. result() still returns the complete list.
  • SmbTask.wait() resolves when the task completes without converting the result — useful after consuming streamed entries.

Server-side copy times depend on the server's file system.

  • Listing: directories are read with raw QUERY_DIRECTORY requests, and follow-up lookups (subfolders, childCount, SD) are pipelined on one connection. Each directory is opened once.
  • Delete, copy, duplicate, and getPathInfo use the same engine. getPathInfo reads the item itself instead of listing its parent folder.
  • Server-side copy: file data is copied inside the server (FSCTL_SRV_COPYCHUNK_WRITE) instead of through the device. If the server does not support it, files are copied through the client as before.
  • Pipelined tree operations: recursive delete and folder creation keep up to 16 requests in flight, and recursive copies copy up to 8 files at once.

Other

  • Listing entries arrive in server order.
  • getPathInfo('/') returns the share root (was NotFound), and links resolve to their target.
  • An empty folder whose server answers STATUS_NO_SUCH_FILE lists as empty instead of failing.
  • getPathInfo and includeSecurityDescriptor omit the SD only when access to it is denied; any other SD failure fails the task.
