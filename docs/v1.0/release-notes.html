Release notes

Changes in each 1.0 release, newest first.

1.0.4

October 8, 2026

Fixes

  • SmbTask.subscribe() now delivers the final state to every listener. Before, only the first listener received it, so later ones — including task.result() — could wait forever after the task had finished.
  • The transfer store no longer notifies listeners when nothing changed.

1.0.3

September 15, 2026

Breaking changes

  • SmbShareList is renamed to SmbShare.
  • dispose() is replaced by the async destroy(), which cancels tasks, disconnects the pool, and stops transfer tracking. The client can't be reused afterwards.
migrate.ts
// before
smb.dispose();

// after
await smb.destroy();

New

  • SmbError.AuthenticationFailed (203) for rejected credentials, logon, and account problems — previously reported as AccessDenied.
  • cancelTransferTasks() cancels every unsettled download, upload, copy, and duplicate task.
  • Every failure is reported as a typed SmbError (transport, timeout, authentication, and server status errors).

Fixes

  • Recursive operations fail on the first error instead of returning partial results.
  • Downloads and uploads write to a temporary file next to the destination and replace it only when complete; failed transfers leave no partial file.
  • Connecting and disconnecting no longer block other work.
  • More reliable cancellation and task completion; tasks waiting for a pool slot can be cancelled.
  • Task and transfer state never moves back to an older snapshot, and bursts of transfer updates are combined to keep the UI responsive.

1.0.2

August 25, 2026

New

  • listDirectory and getPathInfo can return each item's security descriptor (includeSecurityDescriptor, SmbFileInfo.securityDescriptor).

Performance

  • Recursive listings scan subfolders in parallel.
  • The connection pool adds slots on demand for work other than connecting.
